# SheetSet v0.3 release implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish documentation and presentation, verify the complete Android 13+ phone and tablet product, and publish `v0.3.0-alpha.1` with reproducible GitHub evidence.

**Architecture:** Treat the release tag as the artifact source of truth. Keep the existing CI, Pages, and release workflows, update only the product metadata and presentation they consume, and verify downloaded assets independently after publication.

**Tech Stack:** Gradle, Android emulator and ADB, Git, GitHub CLI, GitHub Actions, GitHub Pages, `apkanalyzer`, `apksigner`, and SHA-256.

**Spec:** `docs/superpowers/specs/2026-08-20-sheetset-editor-settings-adaptive-design.md`

## Global constraints

- Complete the settings/adaptive and PDF editor plans first.
- Release version is `0.3.0-alpha.1`, version code 3, and tag `v0.3.0-alpha.1`.
- Release stays a debug-signed prerelease and says so clearly.
- Keep the existing CI, release, latest-release, license, and Pages surfaces.
- Add only useful monochrome Android 13+ and offline badges.
- Do not weaken branch protection or fabricate approval.
- Do not publish until local gates, connected tests, runtime scenarios, and diff review pass.
